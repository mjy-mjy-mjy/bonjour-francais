# 补充一课

把指定课的教材语境、讲义、练习及知识关联一起交付。已有知识优先引用；新增课程内容不代表用户已完成或掌握。

## 开始

1. 定位仓库根目录，读取 `AGENTS.md`、`docs/PROGRESS.md`、开发计划相关章节及 [共用维护流程](../../../docs/MAINTENANCE_WORKFLOW.md)。这些文件中的当前事实优先于本 Skill 的示例。
2. 检查分支、HEAD、工作区和远端；保留其他窗口修改。按共用流程选择已有任务卡，或建立不冲突的 `C课号-序号` 任务卡，登记课号、资料、基线、范围和验收。
3. 从用户指令和当前资料确定教材／册次、课号及可用笔记。课号不明确且不能唯一判断时，只询问缺失的范围；不要仅因第21课是占位页便自动选择它。缺教材资料时，先做可核实的结构与引用盘点，再按共用流程记录待核对项。

## 实现

1. 读取 `lessons/catalog.json`、`content.js` 中相关课次、目标 `lessons/NN.json`（若存在）、相邻课程、`knowledge/README.md` 及有关知识记录。沿用当前课程格式与教材顺序。
2. 在任务卡列出本课知识变更：知识点、已有ID／新条目、核心／复习／拓展／识别、来源章节、处理方式。先区分本课新教内容与已学内容，综合课不凑造新语法。
3. 补充本课目标、中文讲解、适用的结构／变位／词汇／发音与交际内容、原创例句、练习和答案。依据实际材料组织栏目，标清教材内容与本站补充，不杜撰原文、页码或音轨。
4. 对照共享数据处理每项知识：
   - 已有动词记录且本课完整展示六人称时，使用现有占位符，并增加真实完整表的来源绑定；只提及单词或固定搭配时，不伪造完整表引用。
   - 确有新的完整现在时表时，按现有 schema 添加记录并人工核对。其他时态或知识类型按共用流程处理，避免把现在时记录改成另一时态。
   - 其他已有知识复用原有语义技能ID，增加真实章节引用；未共享的规则保留课程权威正文。只有独立学习目标且已有内容支撑时才新增技能节点，依据知识基础设置依赖，不按课号机械串联。
5. 核对 `categorySections`、听力说明、课程目录与入口，使分类页、课程、技能及知识库相互可达。仅调整实现本课所需的字段；不扩展全站布局。
6. 保留已有章节、题目ID、答案语义、笔记键和旧备份。新增题目用唯一ID；更正旧题含义有兼容风险时单独说明并按仓库协议处理。

## 验收与交付

按共用流程运行内容／应用检查、人工语言核对和相关桌面浏览器用例，记录真实结果及未验项。重点检查新课路由、章节跳转、分类搜索、答案／判分、旧记录与共享知识链接；不必为每课重做全套视觉改版。

更新任务卡和进度：本课补了什么、共享知识复用了什么、技能新增／关联了什么、还有哪些待核对内容。用户未明确确认的学习完成与掌握状态保持原样。按当前会话和仓库授权提交推送；推送与Pages发布分别报告。

## 调用示例

> 使用 $francais-add-lesson，补充第21课。我提供的笔记是……请同步维护共享知识和技能关系。

> 使用 $francais-add-lesson，完善第18课的否定说明，其他课只改必要的共享引用。

本 Skill 不自动执行单元整理；需要跨课归并时使用 [francais-review-unit](../francais-review-unit/SKILL.md)。
