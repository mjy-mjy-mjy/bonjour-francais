# 单元与跨课整理

在明确范围内检查课程、知识库、技能树是否一致，修复有证据的遗漏与重复，交付整理结果。重复知识多次出现通常应补来源和教学角色，而不是多建节点。

## 开始

1. 定位仓库根目录，读取 `AGENTS.md`、`docs/PROGRESS.md`、开发计划相关章节及 [共用维护流程](../../../docs/MAINTENANCE_WORKFLOW.md)。核对代码与远端，登记任务、范围、基线、涉及文件。
2. 确定教材／册次、单元或起止课号。单元与课次以当前目录为准，不把固定“四课一单元”写成永久规则。范围无法唯一判断时，先盘点当前资料并询问范围，不默认整理全部课程。
3. 优先续用与范围匹配的活动任务；否则建立不冲突的 `CURATE-U单元-序号` 或 `CURATE-课次范围-序号` 任务卡。仅评审／只出清单时按用户要求执行；一般整理请求应修复范围内可确认的问题。

## 整理

1. 逐课读取作者源、课程章节、已有语义技能与共享知识；需要时读取相邻课判断前置关系，但不自动扩展修改范围。
2. 建立可追溯清单：知识点、稳定ID、课次／章节、核心／复习／拓展／识别、共享状态、发现问题与处理结果。区别完整变位表、零散形式和识别词；不把提及次数当成知识覆盖。
3. 检查并修复：
   - 同一知识是否重复建项；已有记录缺少的真实出处是否应补齐。
   - 普通／代词式、不同语式／时态、相似语法的含义和适用范围是否分清。
   - 已共享的课程表与手册是否来自同一源；未共享内容是否仍有明确的课程权威正文。
   - 已实现技能是否有对应内容和掌握标准；规划节点是否被错误标成已实现。
   - 技能依赖是否表达真实基础，有无环、无效引用或没有必要的课号链；课程与知识能否双向跳转。
4. 优先补引用、澄清范围、修正内容与依赖，不默认合并或删除稳定ID。确需合并时，先保留旧入口与个人记录兼容；无法安全处理的合并记为独立后续任务，不强行改ID。
5. 对支持范围内的完整变位表完成共享绑定。其他语法类型尚无共享格式时，可在本范围完成分类／来源盘点及引用修正，将正文迁移登记为明确后续任务；本 Skill 不隐含授权建设全新知识模块。用户明确要求实现某个模块时，另按该任务验收。
6. 补充跨课辨析、易错点与复习顺序，复用原例句或标注本站原创。不得因单元整理给用户自动打掌握标签，或生成没有依据的测评分数。

## 验收与交付

按共用流程选择检查：只有盘点文档时检查链接、来源和状态；修改知识或课程时运行对应构建／功能检查并核对语言；关系或界面变化时检查桌面浏览器、深链接与旧自评记录。范围外课程仅做受影响的兼容回归。

任务卡需列明已修复项、已核对范围、待核对项、未迁移正文和后续动作；进度页仅汇总并链接。按当前授权提交推送，独立记录Pages验证状态。不要把本单元已整理写成全部A1已覆盖，也不自动开始下一课或下一阶段。

## 调用示例

> 使用 $francais-review-unit，整理第5单元（第17—20课），核对重复规则、共享知识与技能依赖，修复范围内可确认的问题。

> 使用 $francais-review-unit，盘点第1—16课的否定与提问，先输出清单，不修改应用。

需要新增／完善某一课时使用 [francais-add-lesson](../francais-add-lesson/SKILL.md)。
