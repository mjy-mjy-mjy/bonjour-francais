# 课程与知识的持续维护

建议每学一课增量维护，每学完一单元集中整理；用户也可指定任意课次范围。维护频率是工作建议，不是自动任务。新增讲义、学习完成、技能掌握分别记录，后两项以用户明确确认或其浏览器操作为准。

## 两个可复用入口

| 入口 | 使用时机 | 主要交付 |
| --- | --- | --- |
| [francais-add-lesson](../.agents/skills/francais-add-lesson/SKILL.md) | 新增或完善指定一课 | 本课内容、共享知识增量、技能关联、验证与交接 |
| [francais-review-unit](../.agents/skills/francais-review-unit/SKILL.md) | 单元复盘或指定范围跨课整理 | 来源与重复清单、可确认的问题修复、知识／技能关系与未完成项 |

两者共享下述约定，具体步骤由各自SKILL.md维护。一般只调用符合当前目标的入口；用户同时要求补课与整理时先补课再整理，沿用一个清楚的任务范围，不重复维护同一记录。

## 发现与跨窗口使用

Skill保存在仓库 `.agents/skills/`，随Git提交分发；`agents/openai.yaml` 提供可选显示信息。支持仓库Skill发现的Codex客户端可在重新加载仓库／开启新会话后发现，并使用 `$francais-add-lesson` 或 `$francais-review-unit` 调用。是否出现在当前客户端的选择器以实际发现结果为准；创建文件本身不代表已安装到账号全局，也不会修改已经开始的会话工具列表。

未自动发现时，直接提供明确指令：

> 请读取并执行 `.agents/skills/francais-add-lesson/SKILL.md`，补充第21课。资料如下：……

> 请读取并执行 `.agents/skills/francais-review-unit/SKILL.md`，整理第17—20课。

其他模型或窗口可以读取相同Markdown流程；不保证其客户端原生支持 `$` 调用。先同步仓库并读当前AGENTS和进度，不能依赖上一窗口记忆。只有聊天能力、没有仓库读写／浏览器／Git能力的会话只能协助整理草稿与清单，不能声称已修改、验收或推送。

## 开工与资料

1. 遵循 [AGENTS](../AGENTS.md)，先读 [进度](PROGRESS.md)，再读 [开发计划](DEVELOPMENT_PLAN.md) 和相关任务卡；检查分支、基线、工作区与远端。用户当前范围优先，保留其他窗口修改，不默认启动代理或新建worktree。
2. 已有活动任务可续用；否则按 [任务模板](tasks/TEMPLATE.md) 建卡，使用不冲突的ID。登记执行窗口、范围、资料、基线、修改文件、验收和待核对项；纯文档小修可只更新进度。
3. 优先使用仓库已有材料与用户资料；核对教材范围时记录能追溯的公开来源。来源不足时区分“已核实教材内容”“本站原创补充”“待核对”，不要编造教材原文、页码、阅读正文或录音编号。缺关键资料只询问必要信息，继续与其无关的盘点和兼容工作。不能验证的讲义不标为教材核对完成。
4. 默认完成范围内必要的编辑与验证。只有评审请求时不自动改应用；不要把流程示例的第21课或第17—20课当成此次用户授权范围。

## 作者源与稳定关系

| 内容 | 权威位置／维护方式 |
| --- | --- |
| 课程讲义与题目 | `lessons/NN.json`；目录见 `lessons/catalog.json`，基础单元／题目等另见 `content.js` |
| 技能索引 | `knowledge/skills.json`；已有语义优先复用ID，新增依赖需有知识依据 |
| 已共享完整现在时 | `knowledge/verbs.json`；课程六人称通过占位符绑定，细则见 [knowledge维护说明](../knowledge/README.md) |
| 其他知识正文 | 未迁移前保留课程权威正文与可追溯引用，不复制另一套需人工同步的正文 |
| 生成文件 | `course.js`、`lesson14.js`、`skill-tree-data.js`、`verb-data.js` 和index资源指纹，通过构建更新 |

不改已有路由、章节ID、题目ID、笔记键与语义技能ID来满足新命名偏好；显示标题可独立修订。知识新增与技能新增不是一一对应，同一技能可关联多课、多条变位。用户自评数据与查阅范围独立，不能按新增内容批量重置或标记掌握。

## 扩展现有覆盖范围

当前共享动词仅支持第1—16课已有完整现在时，验证器、筛选UI、测试与范围说明有相应边界。新增第17课及以后完整表，或增加其他时态时，先识别边界再处理：

- 若用户要求扩展共享范围，按该次明确范围一并更新源数据、必要的校验／筛选／展示、构建与测试，更新出处与范围说明。其他时态需先确定明确的语式／时态格式与UI，不把过去时填进 `present-*`。
- 若本次只补课程，而知识类型的共享支持尚不存在，课程正文可先保留，技能用真实章节引用；任务卡列明“课程已补充、共享迁移待做”。不要为了强行共享拖入整库重构。
- 新增课程或技能可能使固定数量测试失效。按真实增量更新当前覆盖断言，同时保留旧课程、旧ID与旧备份断言；不得删除失败测试或重写兼容基线来掩盖退化。`scripts/fixtures/k1-legacy-signatures.json` 是历史保护基线，不是新课的数量上限。
- 任务卡的历史盘点与截图是当时证据，新增覆盖另记，不静默重写为当期已验收结果。

## 检查与交付

内容／应用变更从仓库根目录按顺序运行，失败时先修复，不继续提交：

```sh
python3 scripts/build-course.py
python3 scripts/check-site.py
for asset in *.js; do node --check "$asset" || exit; done
node scripts/app.test.cjs
node scripts/map.test.cjs
node scripts/skill-tree.test.cjs
node scripts/verbs.test.cjs
```

共享构建相关修改另运行 `python3 scripts/test_verb_build.py`。核对各命令退出状态和真实用例数，不把历史数字写成此次结果。纯Skill／文档修改检查元数据、路径、链接、任务一致性与 `git diff --check` 即可，不运行无关应用测试。

语言内容需核对来源、变位、性数、例句及核心／拓展边界；自动测试不证明语言准确。有页面或关系变化时按影响检查实际桌面页面、课程／技能／知识链接、搜索／筛选、答案与旧记录。优先2K／4K桌面及系统缩放后的CSS可用视口，记录CSS尺寸、DPR与浏览器缩放；手机专项仍延后，不能声称已验。浏览器依赖不可用时如实记录未验项与影响，不能复用历史截图充作本轮证据。

新增资源检查Pages清单、加载顺序、缓存指纹和子路径；不需要修改公开邀请数据。更新任务卡和进度，列明范围、修改、真实验证、未完成内容和下一动作。按当前用户及仓库授权提交推送，不重复询问已有授权；核对远端提交。推送、部署工作流成功、线上产物验证分别记录。

最终交付说明：补了哪些课程／知识、复用了哪些关系、实际验证及限制、提交SHA与推送状态。学习记录或私人备份不提交到公开仓库。
