# 法语学习网站改造计划

版本：1.8 · 更新日期：2026-10-29

本文件维护产品目标、架构边界、任务依赖与验收标准；当前覆盖数量、任务状态、学习位置、发布证据及下一步统一见 [PROGRESS.md](PROGRESS.md)。历史交接见 [archive](archive/2026-10-handoffs.md)，统一协作入口见 [AGENTS.md](../AGENTS.md)。

## 1. 用户目标与优先级

长期目标是通过持续学习和听说读写训练达到法语 NCLC 7。网站首先服务于个人知识学习、整理和复习，后续再逐步支持考试准备。教材学习完成度不能直接等同于语言能力或考试等级达标。

以《你好！法语》A1 / Le Nouveau Taxi! 1为教材起点。学习位置与掌握程度分别记录，具体状态不在本计划重复维护。

已确认的核心诉求：

1. 按教材、级别／册次、单元、课，直观看到对应词汇、语法、动词变位、发音、文化与交际知识。
2. 提供独立知识库，能跨课次集中查阅同类知识；例如在一个模块查看所有已收录动词变位，再按 A1、A2 等学习阶段筛选。
3. 两种入口共用知识内容，能够互相跳转，持续学习后知识能逐步汇总成体系。
4. 做题和互动目前属于次要功能。后续进入应试准备阶段，再根据实际考试选择增加专项练习和模拟考试。

近期顺序（2026-10-29按用户要求调整）：DOC-02管理整理 → VIS-01代表性视觉样板 → VIS-02推广 → K1-01至K1-05共享动词知识库。K2／K3与后续课程按需求推进，考试训练保持后期范围。用户新的明确需求可调整顺序，调整时同步当前进度和任务卡。

本轮授权仅落实文档整理；视觉方向已纳入计划，具体样板、参数和页面实现尚待后续工作验证。

每日刷题、间隔复习、打卡、自动评分和云端同步暂不作为本轮前置任务。现有小测、错题、笔记等继续保留。

## 3. 信息架构与页面行为

### 3.1 按教材学习

层次：教材 → 级别／册次 → 单元 → 课 → 本课知识总览与详细讲解。

- 第一屏能看出本课涉及哪些词汇、语法、动词变位、发音、文化与交际内容。
- 区分教材核心、本课复习和补充拓展。综合运用课没有新语法时如实说明，不为凑栏目编造内容。
- 总览中的知识点可定位到本课讲解，并进入知识库查看统一内容和其他关联课次。
- 保留完整讲义、参考答案、打印、笔记和既有小测。
- 已完成课次、当前复习范围、最近浏览位置应有不同含义；查阅旧课不应被当成新的正式学习进度。

### 3.2 知识库

| 模块 | 分类／筛选 | 主要展示 |
| --- | --- | --- |
| 动词变位 | 等级、时态／语式、动词组别、代词式用法、课次范围 | 六人称变位、变化提示、含义、搭配、例句、发音提醒及来源课次 |
| 语法 | 冠词、名词与形容词、代词、句型、动词时态等；再按等级筛选 | 规则、结构表、例句、辨析、易错点、关联知识与课程 |
| 词汇 | 主题、课次、等级 | 词性、性数、含义、搭配、例句 |
| 发音 | 音素、拼读、连读、联诵等 | 说明、例词、对比，后续可添加音频 |
| 文化与交际 | 主题、生活场景、课次、等级 | 背景说明、使用场景、常用表达 |

动词变位属于语法知识，但因复习频率高，提供直接入口；语法索引应链接到同一套变位内容。

首期仅开放实际完成的动词模块。A2 等尚无内容的筛选应隐藏或明确标注未收录，不能展示似乎完整的空目录。

动词模块交互要求：

- 默认可浏览变位表，不需要先做题或逐课寻找。
- 支持中文含义和法语原形搜索；处理大小写、常见撇号形式，并明确重音搜索策略。
- 可按 A1 和第 1—16 课等范围查阅。跨设备时首期允许手动选择范围，不依赖云端记录。
- 普通形式与代词式用法、第三组与不规则变化不能混为同一种分类维度。
- 筛选结果显示已收录数量及覆盖范围；“全部”指全部已收录，不代表全部法语动词。
- 来源课次可以点击，返回已有课程或具体知识章节。
- 等级、筛选或知识详情尽量使用可分享的安全 URL 表达，支持刷新及浏览器前进后退。

### 3.3 首页与导航

突出“按教材学习”和“知识库”，保留当前阶段提示、最近查看和笔记入口。已存在的七类学习页需有平滑过渡，避免出现同名入口却指向不同数据副本。听说读写任务继续保留其课程和技能意义，不强行塞入语法分类。

首页大范围改版放在动词试点验证之后；第一阶段先提供清晰可见的知识库／动词入口。

### 3.4 知识地图、技能树与视觉改进

2026-10-30：地图优化分为三个目标：[MAP-03](tasks/MAP-03.md)定位／往返／详情／技能入口；[MAP-04](tasks/MAP-04.md)图鉴按知识／按课程双入口，复用已有引用关联及浏览状态恢复；MAP-05单元标签、状态与桌面宽屏视觉，路线先验证样板。前两项已有实现与自动验收，MAP-05尚未实施；验证及发布状态统一见PROGRESS。

大陆表达教材旅程，技能树表达知识关系，两者与课程、知识库互相链接。保留七个入口，同时区分语音／词汇／语法基础与听说读写运用；允许跨分支关联，不复制权威知识正文。

- 总览优先呈现当前A1真实内容，未来阶段收进明确的规划入口；不得用占位方向填充主要学习空间。
- 分支使用主题中心、知识模块和具体技能的层级；深墨蓝作为技能树基调，金色优先用于选择和掌握状态。分支可辅以图标与少量颜色，状态同时具备文字／形状标记。
- 压缩顶部品牌、标题和统计区域；画布为主体。选中节点突出直接基础与后续关系，淡化无关连线，清楚表达方向和关系含义。
- 语义区分建议基础、组成部分、相关知识；现有 `requires` 仍表示建议基础，不直接充当父子分类。新增字段及迁移在后续数据任务中确定，VIS-01不擅自变更数据协议。
- 本轮优先2K／4K电脑浏览器：画布与详情协调，改善宽屏空间分配、文字尺寸与关系密度，避免全景适配把节点缩得过小；保留关闭、返回与阅读位置。手机详情和触摸专项延后至VIS-MOBILE，不阻塞桌面交付，维持已有响应式基础。
- 提供日常查阅的列表入口，并与图形选择、搜索和深链接保持一致。共享正文在K1阶段接入：核心规则／结构表／例句优先，自评与来源随后；样板不能靠复制另一份权威正文完成。
- 地图保留已有底图；先统一导航、状态和详情操作，不重绘大陆或全站换主题。尊重减少动态效果偏好。

先以动词与时态分支验证2K／4K桌面样板，再推广。以2560×1440、3840×2160为桌面参考，另检查缩放后较小的CSS视口；记录deviceScaleFactor等实际参数，不将物理分辨率等同浏览器可用尺寸。实现参考与任务边界见 [技能树方案](SKILL_TREE_PLAN.md)和 [VIS-01](tasks/VIS-01.md)。

### 3.5 考试训练

后期根据用户实际考试选择设计听说读写专项、题型与模拟考试。保留题目和知识点建立关联的可能；当前不建立空的考试题库、评分服务或完整考试界面。

## 4. 内容与数据设计

### 4.1 一份知识内容，多处展示

课程保留教材语境、学习目标、章节顺序和本课说明；可复用的知识由独立记录维护。课程与知识是多对多关系，同一知识可以出现在多课、多个阶段。

以 `faire` 现在时为例：独立维护变位与通用说明，第 14 课引用；知识库展示同一条记录；后续课程引用时可以补充自己的例句或复习说明，不能另复制一套权威变位表。

保留足够的知识粒度：一条规则配完整结构与例句；一个动词的一个时态／语式可成为一条变位记录。无需将每句话拆成实体。

### 4.2 最小数据约定

动词模块格式已在 `knowledge/verbs.json` 实施，字段及占位符约定见knowledge/README.md；下表仍作为其他共享知识扩展的要求，不表示所有类型均已迁移。后续模型复用已确定字段，不自行另造同义格式。

| 对象 | 必需信息 |
| --- | --- |
| 教材／册次 | 稳定标识、名称、级别／册次及单元关系；当前仅填实际使用的教材 |
| 课程引用 | 教材／册次标识、课次、原路由／章节锚点，以及核心／复习／拓展角色 |
| 知识记录 | 稳定 ID、类型、标题、搜索别名、正文或结构化内容、关联知识 |
| 知识与课程关系 | 对应课程、章节、学习阶段和教学角色，必要时附本课语境说明 |
| 动词变位 | 原形、用法、语式、时态、六人称形式、中文含义、变化提示及例句 |
| 来源信息 | 教材范围、核对资料、整理说明和审校状态 |

等级关联具体知识及教材学习阶段，不把一个动词整体永久归入 A1 或 A2。CEFR 学习标签用于组织内容，不作为已达到 NCLC 等级的证明。

普通动词和代词式形式需要明确关联；教材中仅以固定搭配或特定人称出现的用法，应附实际使用说明，不机械生成容易误导的例句。

### 4.3 渐进提取与维护

1. 盘点第 1—16 课已有内容，先建立动词及出处清单，标明核心、复习、拓展。
2. 提取变位表等复用数据并核对；允许自动提取辅助，但不能把 HTML 正则抓取结果直接当成可靠知识库。
3. 让原课程相应部分通过引用展示同一数据，保留原章节 ID；未迁移正文继续保留。
4. 稳定后用相同原则整理语法、词汇、发音等内容。
5. 新课程使用已确定格式，已有知识优先引用，只新增新增知识和课程语境。

动词作者数据位于 `knowledge/verbs.json`，课程用占位符引用共享词形，通过现有构建生成课程和 `verb-data.js`；其他知识类型按后续任务扩展。不要同时维护两份需要人工同步的权威内容。

### 4.4 持续维护入口

逐课新增／完善使用仓库Skill `francais-add-lesson`，单元或指定范围跨课整理使用 `francais-review-unit`。建议每课小步补充、每单元集中整理；是否执行及具体范围由用户指定，不自动开展下一课或下一阶段。

两个Skill共用 [持续维护流程](MAINTENANCE_WORKFLOW.md)，维护课程、共享知识、稳定技能关系及验证交接。尚无共享格式的知识先保留课程权威正文并列出迁移待办；扩展现有范围时同时处理校验、展示和测试。课程内容、学习完成与个人掌握状态独立。交付与发现限制见 [SKILL-01](tasks/SKILL-01.md)。

## 5. 技术边界与兼容要求

- 保留静态托管和原生 JavaScript。无需以换框架、增加登录或数据库作为知识库前提。
- 随改造抽出知识数据访问、知识展示、搜索索引与学习记录模块，避免把所有新逻辑继续塞进 `app.js`；无需一次性重写全部代码。
- 保留 `#lesson/14` 等现有课程路由和章节锚点。未来其他教材可能重复课号，应通过教材／册次标识区分，同时为当前数字课号保留兼容入口。
- 第14课已统一作者源，继续保护 `content.js` 基础题、兼容别名、分类引用和笔记键；不得重复或遗漏题目，不改写旧题目 ID。
- 知识点 ID 与展示标题分离。标题修订不应导致链接或关联记录失效。
- 调整学习记录结构时增加版本与迁移。未知或已移除题目应单独处理，不能因此放弃整份进度或笔记；不能编造旧记录中不存在的答题时间。
- `PROGRESS.md` 是阶段性事实与交接摘要，浏览器记录是个人操作数据；目前不自动同步。将来若网站读取阶段摘要，应明确唯一数据来源，不要求重复手改 Markdown 和 JSON。
- 新增脚本、数据、路由或模块后检查 GitHub Pages 子路径、加载顺序、缓存版本、打印与部署产物。
- 自动化生成文件只通过脚本更新，包含 `course.js` 及后续类似产物。

按变更范围运行现有检查，命令见 README：

```sh
python3 scripts/build-course.py

for asset in *.js; do node --check "$asset" || exit; done
node scripts/app.test.cjs
node scripts/map.test.cjs

```

构建会写入course.js、skill-tree-data.js和index.html：正常实现任务按需更新并检查diff；仅评审或环境验证时在临时副本构建并比较产物。Node测试须确认实际用例执行；当前环境 `node --test scripts/*.test.cjs` 只汇总为三个文件，以上逐文件运行可查看真实用例数。纯文档修改只检查链接、任务一致性及diff，无需重跑无关应用测试。

移除或调整文件后，同步更新检查命令、测试加载方式、工作流和 README，不保留指向失效文件的命令。

新增验证聚焦真正的风险：重复 ID、无效课程引用、知识覆盖遗漏、筛选与搜索、旧备份迁移和课程链接兼容。自动测试不能证明法语讲解准确，内容还需人工核对出处、变位、词性及例句。

标记任务完成需说明：实现内容、涉及文件、实际验证、已知限制以及提交／PR。若只有本地实现或待合并分支，不能写成主站已上线。

## 8. 跨模型、跨会话与跨窗口协作

### 记录职责与事实来源

| 文件 | 唯一职责／维护方式 |

当前事实优先核对实际代码／数据和对应验证证据。学习状态与产品决定来自用户明确陈述；模型建议单独标注。证据矛盾或缺失时记为待核验，不能挑选较乐观的状态。任务卡保存详细证据，进度页只汇总并链接；避免每次在多个文件手填同一数量。

### 开始与并行工作

1. 按AGENTS入口读取当前进度及相关任务，检查分支、HEAD、工作区修改和可获取的远端／PR状态；读不到远端时说明范围，不假定已同步。
2. 明确本轮用户要求；旧“下一步”不能覆盖用户新指令。领取一个具体任务，写明窗口标识、分支、基线提交和允许修改的文件范围；未认领的任务保持待开始。
3. 多窗口优先分配不同文件与任务。不同分支不等于同一工作区隔离；共享检出时不能擅自切换分支。每个云任务已隔离，使用已有检出，不默认创建worktree。
4. 同一知识源、生成产物及总进度由一个整合窗口统一处理；其他窗口写自己的任务卡，合入后由整合窗口运行构建和更新摘要。窗口标识仅供交接，不是自动锁；接手前核对实际修改，不凭过期负责人记录抢占。
5. 用户未要求多代理协作时不自动启动子代理；这些规则也适用于用户自行开启的多个窗口。

### 状态与交接

- 任务使用待开始、进行中、阻塞、待验收、完成；同时独立记录代码／文档是否实现、实际验证、合并和部署。阻塞要有具体原因和恢复动作。
- 按 [任务模板](tasks/TEMPLATE.md)记录范围、非目标、已做／未做、证据与下一动作。小任务无需新建复杂文档，但仍需在进度中留下足够交接。
- 验证记录包含命令、实际结果、基线／对应提交、运行时间和限制。历史通过、跳过、未运行及失败分开写；日期时间采用北京时间并注明时区。
- 提交／合并前重新检查并保留其他窗口有效修改，不强制覆盖。不要重置或删除不明来源文件。提交后SHA可从Git查询，无需为回填自身SHA制造循环提交。
- 发布成功需要对应提交的部署证据；线上行为还需产物或功能核验。不能把本地通过、推送或标题“已发布”当成线上验证。
- 交接结束更新当前摘要；已完成长记录移入archive并修复链接。只记录可公开信息，不提交私人备份、凭据或私密对话。

新会话入口示例：

> 请读取AGENTS.md和docs/PROGRESS.md，核对代码状态，再根据本轮要求和当前优先级领取具体任务。读取相关计划与任务卡，保护课程链接、知识ID和个人记录，完成后记录实际验证、未完成项及合并／发布状态。
